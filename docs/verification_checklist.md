# 수집 검증 체크리스트

11주차 수업의 검수 기준을 이 프로젝트에 맞춘 것입니다. 수집을 다시 할 때마다 근거를 적습니다.
"성공했습니다"라는 AI의 말이 아니라 코드, 실행 결과, 데이터로 확인합니다.

| 번호 | 확인할 것 | 통과 여부 | 근거 (직접 본 것) |
|---|---|---|---|
| 1 | API를 실제로 호출했다 (예시 데이터가 아님) |  | 예: `collect.py`의 `requests.get()` 줄 번호 |
| 2 | 원본 응답(JSON)의 구조를 확인했다 |  | 예: `data/raw/boxoffice_20261108.json`의 `dailyBoxOfficeList` |
| 3 | 필요한 항목이 CSV에 모두 들어갔다 |  | 예: 상영 횟수·스크린 수 칸이 숫자 |
| 4 | 원본 JSON과 CSV의 값이 같다 |  | 예: 11/8 1위 영화 관객 수가 양쪽 모두 62,973 |
| 5 | 오류를 정상 데이터처럼 저장하지 않았다 |  | 예: 받지 못한 날짜 목록, 빈 칸만 있는 행 없음 |
| 6 | 요청한 날짜 수와 받은 날짜 수가 맞다 |  | 예: 요청 7일, 받은 날짜 7일, 70건 |
| 7 | 다시 실행하면 새로 수집한다 |  | 예: `fetched_at`이 바뀜 |
| 8 | 인증키가 코드·출력·로그·Git에 없다 |  | 예: 코드에서 키 문자열 검색, `git status`에 `.env` 없음 |
| 9 | 하루 호출 한도를 넘지 않는다 |  | 예: 한도 3,000회, 이번 실행 호출 수 |
