# 수집 검증 체크리스트

11주차 수업의 검수 기준을 이 프로젝트에 맞춘 것입니다. 수집을 다시 할 때마다 근거를 적습니다.
"성공했습니다"라는 AI의 말이 아니라 코드, 실행 결과, 데이터로 확인합니다.

| 번호 | 확인할 것 | 통과 여부 | 근거 (직접 본 것) |
|---|---|---|---|
| 1 | API를 실제로 호출했다 (예시 데이터가 아님) | 통과 | collect.py와 collect_extra.py의 requests.get()으로 호출. 날짜마다 "10건"이 출력됨 |
| 2 | 원본 응답(JSON)의 구조를 확인했다 | 통과 | data/raw/json/boxoffice_20261108.json 5번째 줄에 dailyBoxOfficeList가 있고, 그 아래에 영화 10편이 순서대로 들어 있음 |
| 3 | 필요한 항목이 CSV에 모두 들어갔다 | 통과 | 상영 횟수·스크린 수 칸이 숫자 (11/8 1위 영화 스크린 977개, 상영 3,098회). 상세정보는 장르·국가·관람등급, 공휴일은 날짜·이름·여부 |
| 4 | 원본 JSON과 CSV의 값이 같다 | 통과 | 11/8 1위 영화의 audiCnt가 JSON(19번째 줄)과 CSV 모두 62973. 2~4위도 37117, 32393, 27386으로 같음 |
| 5 | 오류를 정상 데이터처럼 저장하지 않았다 | 통과 | 첫 실행에서 5/19·5/20을 받지 못했고 "받지 못한 날짜"로 따로 표시됨. 빈 행으로 저장되지 않음 |
| 6 | 요청한 날짜 수와 받은 날짜 수가 맞다 | 통과 | 첫 실행 182일 중 180일(1,800건), 이틀 재수집 20건. 합계 182일 1,820건. clean.py 건수 검증표에서 "기간 중 빠진 날짜: 없음" 확인 |
| 7 | 다시 실행하면 새로 수집한다 | 통과 | 첫 수집 fetched_at 2026-11-19T06:19:08, 이틀 재수집 2026-11-19T06:23:48로 다름 |
| 8 | 인증키가 코드·출력·로그·Git에 없다 | 통과 | 키는 .env에만 있음. git status에 .env가 나오지 않음. 오류 메시지는 주소 없이 원인만 출력 |
| 9 | 하루 호출 한도를 넘지 않는다 | 통과 | 영화진흥위원회 한도 하루 3,000회. 11/19 호출은 박스오피스 184회, 상세정보 147회 × 3번으로 약 625회 |

## 기록

- 확인한 날짜: 2026-11-19
- 확인한 사람: 이윤정
- 수집 기간: 2026-05-18 ~ 2026-11-15 (182일)
- 특이 사항: 첫 실행에서 박스오피스 2일, 상세정보 1편(킬링타임)이 일시적 접속 문제로 빠져 다시 받음. 관람등급이 여러 개인 재개봉작은 마지막(최근) 등급만 사용
