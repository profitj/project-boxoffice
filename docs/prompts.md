## 2026-11-16 김유라 — 요건정의서 기반 FastAPI 서버(api.py) 및 Streamlit 대시보드(app.py) 구현

- **사용한 AI**: Claude
- **프롬프트**:
  1. `data/clean/` 및 `data/sample/` 정제 데이터를 로드하여 날짜별 영화 데이터를 반환하는 FastAPI(`api.py`) 및 날짜 선택 시 표와 차트를 띄우는 Streamlit(`app.py`) 기본 뼈대 요청
  2. 1차 코드가 단순 관객 수 조회에 그쳐 팀 요건정의서 필수 요건을 근거로 수정 요청:
     - 개봉 주차 공식(`(날짜 - 개봉일) // 7 + 1`) 도입
     - 당일 전체 평균 회당 관객 수 대비 ±10% 버퍼를 적용한 3단계 편성 의사결정 권고 카드 (확대 > 110%, 유지 90~110%, 축소 < 90%)
     - 전체 상영 순위 표 유지 및 개봉 2주차 영화 시각적 구분(⭐)
     - 수집 기간 내 특정 영화의 날짜별 회당 관객 수 및 당일 평균 추이를 비교하는 시계열 선 그래프(`st.line_chart`)
     - 데이터 부재 및 0건 시 요건정의서 명세 문구(`"조건에 맞는 데이터가 없습니다"`) 통일, 숫자 서식(천 단위 콤마, 소수 첫째 자리) 지정, FastAPI 서버 미구동 시 `ConnectionError`/`Timeout` 예외 처리
- **AI가 준 결과 요약**: `api.py`에 `/api/recommendations`, `/api/movie-list`, `/api/trend` 엔드포인트를 추가하고, `clean.py` 재실행 시 서버 재시작 없이 새 CSV를 읽는 캐시 구조(`DataStore`)를 적용함. `app.py`에는 상단 2주차 의사결정 권고 카드(`st.success`/`st.info`/`st.error`), 전체 현황 표, 영화별 시계열 추이 그래프, 서버 다운 안내 화면을 구현함
- **직접 확인하거나 고친 점**:
  1. **의사결정 기준 명체화 (±10% 룰 적용)**: 
     - 초기 1차 코드는 단순히 당일 평균 미만인 영화만 텍스트로 나열하여 실무적인 편성을 돕지 못했음.
     - 단순 100%(평균) 기준으로 자를 경우 0.1명 차이로 편성 판단이 뒤바뀌는 비현실적 문제가 생기므로, 요건정의서에 `(미정)`이었던 기준을 '평균의 ±10% 구간(90~110%)은 오차 범위 내 현행 유지'로 직접 정의함. 이를 통해 축소(<90%), 유지(90~110%), 확대(>110%)의 명확한 3단계 권고 카드로 분기되도록 재요청하여 구현함.
  2. **실제 데이터 기반 경계값 및 카드 검증**:
     - 구현 후 초록색(확대 권고) 카드가 뜨지 않아 로직을 점검했으나, 수집된 7일치 실제 데이터 중 2주차 영화이면서 110%를 초과하는 영화가 존재하지 않음을 확인함(코드 결함이 아닌 데이터 특성임을 규명).
     - 대신 11월 14일 데이터(유지: 코난·마도카, 축소: 최종면접·모자 쓴 고양이)와 11월 8일 데이터(축소: 하트 오브 비스트)를 통해 유지/축소 판정 카드와 수치 비율(%)이 정상 작동함을 직접 검증함.
  3. **요건정의서 스펙 및 완료 기준 일치 작업**:
     - 2주차 영화만 필터링해 보여주면 전체 상영 현황 비교가 불가능하므로, 전체 1~10위 표를 유지하되 2주차 영화명 앞에 '⭐'를 붙여 한눈에 식별하도록 구성함.
     - 요건정의서 완료 기준(2026-11-08 기준 1위 치이카와 20.3명, 4위 코난 23.9명)과 천 단위 콤마(%,d) 및 소수점(%.1f) 서식이 일치하는지 확인하고, 데이터가 없는 날짜 조회 시 정의서 규칙대로 `"조건에 맞는 데이터가 없습니다"`(st.warning)가 출력되는지 점검함.
